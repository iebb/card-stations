# CSV format

All files are UTF-8 CSV with a header and LF newlines. Codes are text: preserve
leading zeroes and uppercase hexadecimal. Empty cells mean unknown. Tables can
omit unused optional columns; column names have the same meaning in every family.

| Column | Meaning |
| --- | --- |
| `code` | Exact card lookup code, terminal code, or registry code |
| `name` | Primary native name |
| `name_en`, `name_ja`, `name_hanja`, `name_zh_hans`, `name_zh_hant` | Optional names in other languages |
| `station_code` | A distinct physical-station code or an optional terminal-to-station link |
| `line_code` | Line identifier; use `|` between multiple memberships |
| `line` | Line name when supplied by the source |
| `latitude`, `longitude` | WGS84 degrees, both present or both empty |
| `osm_ref` | Actual `node/ID`, `way/ID`, or `relation/ID`; otherwise empty |

`code` and `name` are required. A terminal with `station_code` may leave `name`
empty to inherit it. Do not repeat the same name in a translation column.

- Japanese IC: `code` is five hex characters. `station_code` identifies the
  physical station; `0` denotes a non-station area/ticket code. A name-only code
  without a physical mapping can omit coordinates and `station_code`.
- T-Union: `code` contains its four-character city prefix. The city is also the
  file name, not a repeated column. `terminals/18/<city>.csv` contains 12-hex
  terminals; `terminals/1e/<city>.csv` contains 16-hex terminals. Shanghai CU
  prefixes remain in `cityunion/2000.csv`, separate from TU city `2900`.
- Korean: `code` is the eight-hex station token followed by the four-hex mode.
  Neither component nor any mode labels are repeated as station columns.
  Company grouping does not assert an operator where it is unknown.
- U-money: station and line codes are decimal service IDs. `line_code` records
  memberships; `data/u-money/lines.csv` supplies line names once.

`data/korean/modes.csv` uses `code,name,name_en,name_ja,name_hanja,name_zh_hans,
name_zh_hant,class`. Its `code` is decimal; `class` retains the source's bus/rail
classification. Registry CSVs use `code,name`.

The exact allowed columns and file globs are in `schema.json`. Application-only
compatibility columns are generated by `adapters/`; contributors do not maintain
them. Routing tables are documented in `routing/README.md`.
